# 옵시디언 LLM 위키 (obsidian-llm-wiki)

LLM 위키는 Andrej Karpathy가 [LLM Wiki 아이디어 파일](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)로 제안한 방식입니다. 사람이 자료를 고르면 AI가 요약하고, 기존 문서에 이어 붙이고, 목록과 기록을 관리합니다. 노트가 쌓일수록 AI가 다음 작업 전에 꺼내 쓸 수 있는 "나만의 지식"이 됩니다. 작성자는 이 구조로 8,000개가 넘는 노트를 운영하고 있고, 같은 저장고를 [obsidian-brain-3d](https://github.com/reedodev/obsidian-brain-3d)로 그려 보고 [vault-recall](https://github.com/reedodev/vault-recall)로 작업 전에 찾아 씁니다.

## 준비물 (쓰기 전에 있어야 하는 것)
| 준비물 | 어디에 쓰나요 | 꼭 필요한가요 |
|---|---|---|
| Node 18 이상 | 저장고 만들기, 목록 갱신, 점검 스크립트 | 필수 |
| 비어 있는 폴더 또는 기존 옵시디언 보관함 | 저장고 위치. 기존 파일은 덮어쓰지 않습니다 | 필수 |
| 옵시디언 앱 | 사람이 노트를 읽고 그래프로 보기 | 권장(AI만 쓴다면 없어도 됨) |
| git | 모든 변경을 기록하고 되돌리기(`--git`) | 권장 |
| 위키를 고칠 AI 하나 | Claude Code, Codex 등. 고치는 AI는 하나로 정합니다 | 필수 |

## 바꿔 쓰기: 이렇게 말하세요
에이전트에게 왼쪽처럼 말하면 오른쪽을 바꿔서 실행합니다.

| 이렇게 말하면 | 바뀌는 것 |
|---|---|
| "저장고 이름을 '회사 업무 노트'로 해 줘" | `init.mjs <폴더> --name "회사 업무 노트"` |
| "변경 기록도 남게 해 줘" | `--git` (이후 작업마다 커밋) |
| "원본 폴더에 '회의록'도 만들어 줘" | `10_원본/회의록/` 폴더를 만들고 `운영규칙.md`의 폴더 표에 한 줄 추가 |
| "문서 종류에 '레시피'를 추가해 줘" | `운영규칙.md`의 type 목록과 `scripts/check.mjs`의 `TYPES`에 추가 |
| "확인 상태를 영어로 쓰고 싶어" | `운영규칙.md`의 status 목록과 `check.mjs`의 `STATUS`를 함께 바꿉니다 |
| "다른 AI는 읽기만 하게 해 줘" | `운영규칙.md` 5장(여러 AI가 함께 쓸 때)을 그대로 따릅니다 |

규칙을 바꿀 때는 `운영규칙.md`와 `check.mjs`를 **함께** 고쳐야 점검이 새 규칙을 따라갑니다.

## 처음 만들기
```bash
node scripts/init.mjs ~/MyVault --name "내 지식 저장고" --owner "나" --git
```
- 폴더: `00_받은자료`, `10_원본`(글과기사·영상자막·내메모·작업기록·문서), `20_위키`(자료요약·개념·도구와플랫폼·실전·종합 + `index.md`, `log.md`), `30_결과물`, `80_서식`, `90_첨부`
- 파일: `운영규칙.md`(모든 AI가 먼저 읽는 규칙), 서식 4개(원본·자료요약·개념·실전)
- 이미 있는 파일은 건드리지 않고 `skipped`로 알려 줍니다.

그다음 쓰는 AI의 지시문(`CLAUDE.md`, `AGENTS.md` 등)에 한 줄을 넣습니다.
```
이 저장고를 다루기 전에 운영규칙.md를 끝까지 읽고 그대로 따른다. 작업 전에는 20_위키/index.md에서 관련 문서를 먼저 찾는다.
```

## 자료 넣기 (수집)
1. `운영규칙.md`를 읽습니다.
2. 원본을 `10_원본/<폴더>/YYYY-MM-DD_제목.md`로 저장하고 머리말에 `source_url`, `captured`, `ingest_status: 대기`를 넣습니다(서식: `80_서식/원본.md`). 유료 글은 전문 대신 링크·짧은 인용·요약만 넣습니다.
3. `20_위키/자료요약/`에 **사실만** 요약합니다.
4. `index.md`에서 관련 문서를 찾아 **기존 문서를 먼저 고치고**, 없을 때만 개념·도구·실전 문서를 새로 만듭니다. 모든 위키 문서에 머리말(title, type, status, sources, checked, recheck, tags, created, updated)을 넣고, 확인하지 않은 주장은 `작성자주장`이나 `미검증`으로 둡니다.
5. 목록을 갱신합니다: `node scripts/index.mjs ~/MyVault`
6. `log.md`에 `## [YYYY-MM-DD] 수집 | 제목`을 추가하고, 원본의 `ingest_status`를 `완료`로 바꿉니다.
7. 점검합니다: `node scripts/check.mjs ~/MyVault`. `--git`으로 만들었다면 `git commit -m "수집: 제목"`으로 기록합니다.

## 질문에 답하기
`index.md` → 관련 위키 문서 → 필요할 때만 원본 순서로 읽습니다. 답에는 근거 문서를 `[[문서명]]`으로 붙이고, 확인 상태가 낮으면 그렇다고 말합니다. 위키에 없으면 없다고 말하고 추측하지 않습니다. 다시 쓸 만한 답은 사용자가 원할 때 `20_위키/종합/`에 저장합니다.

## 점검 (월 1회 권장)
```bash
node scripts/check.mjs ~/MyVault          # 사람이 읽는 보고
node scripts/check.mjs ~/MyVault --json   # 다른 도구에 넘길 때
```
목록에 없는 문서, 목록에만 있는 문서, 머리말 문제, 깨진 연결, 다시 확인할 날이 지난 문서가 있으면 종료 코드 1입니다. 연결 없는 문서와 정리 대기 원본은 참고로 보여 줍니다. **고치기 전에 보고서를 먼저 사용자에게 보여 주고 확인받습니다.** 작성자의 노트 8,015개 저장고에서 약 8초 걸렸습니다.

## 하지 않는 것
- `10_원본`의 내용 수정(`ingest_status`만 예외), 위키 문서 삭제. 틀린 문서는 `status: 폐기`와 이유를 남깁니다.
- 비밀번호·API 키·개인정보·다른 사람의 대화나 메일 원문 저장
- 여러 AI나 여러 컴퓨터가 동시에 위키를 고치기

## 한계
- 스크립트는 구조를 만들고 점검할 뿐이고, 요약과 연결의 품질은 위키를 다루는 AI와 사람의 확인에 달려 있습니다.
- `index.mjs`는 각 문서 본문의 첫 문장으로 목록을 만듭니다. 더 좋은 한 줄 설명이 필요하면 AI가 `index.md`를 직접 다듬습니다(다시 `index.mjs`를 돌리면 덮어씁니다).
- 링크는 파일 이름 기준으로 확인합니다. 같은 이름의 노트가 두 폴더에 있으면 구분하지 못합니다.

## 출처와 영감
- **LLM Wiki 아이디어**: Andrej Karpathy가 공개한 [LLM Wiki 아이디어 파일(llm-wiki.md)](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)에서 왔습니다. 사람이 자료를 고르고 AI가 위키를 계속 고쳐 나가며, 옵시디언으로 결과를 본다는 핵심 방식은 이 글의 것입니다.
- 원문은 일부러 구체적인 구조를 정하지 않은 아이디어 문서입니다. 이 스킬의 한국어 폴더 이름(받은자료·원본·위키·결과물), 머리말 항목, 확인 상태 다섯 단계, 운영규칙 문서, 점검·목록 스크립트는 작성자가 실제로 저장고를 운영하며 정한 것이고, 원문의 글이나 코드를 옮기지 않았습니다.
- 더 알고 싶다면 원문을 직접 읽어 보는 것을 권합니다.
